Chapter 1: The Core Philosophy & Hardware Foundations

The Truth: A Data Structure is simply how data is arranged in RAM. An Algorithm is simply the recipe to eliminate unnecessary CPU work. Every new data structure was invented to fix a physical flaw in the previous one.
The Only Two Physical Layouts in RAM:
  • 1. Contiguous (Array): Elements sit side-by-side. CPU uses instant math: Address(i) = Base + i * Size ($O(1)$ random access). High CPU cache hit rate. Downside: Fixed size, expensive $O(N)$ insertion/deletion in the middle.
  • 2. Scattered / Linked (Pointers): Elements sit anywhere free in RAM. Each node stores the memory address of the next. Downside: No random index access ($O(N)$ traversal), pointer memory overhead (8 bytes per pointer in 64-bit OS).
  • The Big Secret: Every other structure (Stack, Queue, Tree, Heap, Graph, HashMap) is just an Abstract Data Type (ADT) — a set of behavioral rules enforced on top of an Array or Linked Nodes!

Chapter 4: The 3 Supporting Weapons (Hidden Test Case Protectors)

1. Math & Modulo Arithmetic ($10^9 + 7$):

In almost every Infosys SP question, numbers exceed 64-bit limits. Always use: (A + B) % 1_000_000_007 and cast products to (long) before multiplying: (int) (((long) a * b) % MOD).

Euclidean GCD in $O(\log(\min(A, B)))$: long gcd(long a, long b) { return b == 0 ? a : gcd(b, a % b); }

2. Bitwise Magic Tricks:
  • x & (x - 1) — Instantly clears the lowest set bit (counts 1-bits in number).
  • x & (-x) — Isolates the lowest set bit.
  • a ^ a = 0 — All duplicates cancel to 0; isolates single unique element in $O(N)$ time and $O(1)$ space.
3. Advanced Range Trees (Segment Tree & Fenwick Tree):

Solves problems where an array has BOTH rapid updates ($O(\log N)$) AND rapid range queries ($O(\log N)$) across $10^5$ operations. Prevents Time Limit Exceeded (TLE).
